พร้อมชื่อหน้าหลังบ้านและชื่อ RPC จริงที่อยู่เบื้องหลังแต่ละปุ่ม เพื่อให้คนที่ไม่ได้เขียนระบบ
(หรือคนเดิมที่กำลังรีบ) ทำตามได้

(`AdminTournamentContext`) — ก่อนกดอะไร **ดูชื่องานบนหัวจอก่อนทุกครั้ง** กรรมการ, token,
ประกาศ, ข้อมูลแข่งสด และการรีเซ็ต ล้วนแยกต่องาน

## 1) ตั้งงานขึ้นระบบ (ก่อนเปิดรับสมัคร)

1. **สร้างรายการแข่ง** — `/admin/tournaments` → สร้างใหม่ หรือ **"คัดลอกจากรายการเดิม"**
   (`CloneTournamentSheet`) ซึ่งจะก็อป **รุ่นทั้งหมด + กฎ กติกา + กำหนดการ** มาให้ แล้วเหลือ
   แค่แก้วันที่ · สิ่งที่ **ไม่** ถูกคัดลอกโดยเจตนา: รูปแบนเนอร์/แผนผังงาน (งานใหม่ใช้โปสเตอร์ใหม่
   และการชี้สองงานไปที่ไฟล์เดียวกันทำให้ลบรูปงานหนึ่งพังอีกงาน) และสถานะ — สำเนาลงเป็น
   **ฉบับร่าง (draft)** เสมอ ฉบับร่างไม่โผล่ฝั่งสาธารณะ
2. **ตั้งค่างาน** — `/admin/tournament`: ชื่อ, แบนเนอร์, แผนผังงาน, วันแข่ง,
   **วัน-เวลาเปิด/ปิดรับสมัคร**, และ **ผู้รับเงิน (merchant QR ของร้าน — K SHOP / Thai-QR)**
   ถ้าไม่ได้ตั้ง `NEXT_PUBLIC_DEFAULT_MERCHANT_QR` ไว้ ฟอร์มจะไม่ยอมบันทึกจนกว่าจะวาง QR payload
3. **รุ่น/หมวด** — `/admin/categories`: โควตาที่นั่ง, ค่าสมัคร, ช่วงระดับฝีมือ (min/max
   `power_level`), **ช่วงอายุ**, และ **รุ่นที่เล่นควบกันได้** (เช่น 9×9 + 13×13 ที่แข่งคนละเวลา)
   — ทุกข้อถูกบังคับซ้ำฝั่งเซิร์ฟเวอร์ใน `reserve_seats` หน้าเลือกรุ่นของผู้สมัครจะโชว์เฉพาะ
   รุ่นที่คนนั้นมีสิทธิ์ลงจริง
4. **กฎ กติกา + กำหนดการ** — `/admin/rules` (block editor) และตัวสร้างกำหนดการใน
   `/admin/tournament`
5. **โค้ดส่วนลด / สมัครฟรี** (ถ้ามี) — `/admin/codes`
6. **ฐานข้อมูลระดับฝีมือให้เป็นชุดล่าสุด** — `/admin/database` → Sync จาก Google Sheets
   (DAN/KYU/AWARD) นำเข้าเสร็จระบบซิงก์ระดับของทุกคนที่ลิงก์ทะเบียนบุคคลไว้ให้เอง
   ดู [rank-databases.md](./rank-databases.md)
7. **เผยแพร่** — `/admin/tournaments` → สลับสถานะเป็น **เผยแพร่ (published)**

## 2) ตั้งกรรมการ + token (ทำล่วงหน้า อย่ารอเช้าวันแข่ง)

- **`/admin/judges`** — เพิ่มกรรมการเป็นรายบัญชีด้วยอีเมล (`admin_set_judge`) และกำหนด
  **รุ่นเริ่มต้น** ต่อคน · รายชื่อนี้ใช้กับงานนี้เท่านั้น (ตาราง `tournament_judge`)
- **สร้างบัญชีที่นี่ไม่ได้** — ถ้าขึ้น "ไม่พบบัญชีนี้ในระบบ" (`ACCOUNT_NOT_FOUND`) ให้เจ้าตัว
  ไปสมัครสมาชิกในเว็บก่อน
- **เงื่อนไขที่กรรมการต้องมีครบ 2 ข้อ ไม่งั้นบันทึกผลไม่ได้:**
  1. **ล็อกอินเว็บนี้ในเบราว์เซอร์เดียวกับที่เปิดลิงก์กรรมการ**
  2. **มีชื่อ (ภาษาไทย) ในโปรไฟล์** — คอนโซลใช้ชื่อนี้เซ็นผลทุกครั้ง (`submitted_by`)
     หน้า `/admin/judges` มีแถบเตือนสีเหลืองบอกจำนวนคนที่ยังไม่มีชื่อ พร้อมอีเมลของแต่ละคน
     — เดิมเรื่องนี้รู้ตอนเขาพยายามส่งผลรอบ 1 แล้ว
- **ลิงก์กรรมการ** อยู่บนหน้านี้ (และหน้า `/admin/live`) มีให้ก่อนที่จะอัปโหลดรุ่นด้วยซ้ำ
  จึงบรีฟทีมล่วงหน้าได้ · ลิงก์คือ `https://<domain>/judge/<token>` และ **`token` นั้นคือ
  ด่านทั้งหมด** — ใครถือลิงก์ก็เปิดคอนโซลของงานนี้ได้ การถอดคนออกจาก `tournament_judge`
  ซ่อนแค่ปุ่มของเขา **ไม่ได้** ทำให้ลิงก์เดิมใช้ไม่ได้
- **ถ้าลิงก์หลุดออกนอกทีม:** `/admin/live` → สร้าง token ใหม่ (`live_rotate_token`) แล้ว
  **แจกลิงก์ใหม่ทั้งทีม + แก้ `launcher.properties`** ทันที (ของงานอื่นไม่กระทบ)

## 3) T-1 วัน: ปิดรับสมัคร, ส่งออกรายชื่อ, สำรองข้อมูล

1. **เคลียร์คิวค้างให้หมดก่อน** — `/admin/registrations` (ตรวจสลิป/ยืนยัน-ปฏิเสธ),
   `/admin/division-changes` (คำขอเปลี่ยนรุ่นข้ามราคา), `/admin/withdrawals` (ถอนตัว/คืนเงิน)
2. **ปิดรับสมัคร** — `/admin/tournaments` → สถานะ **ปิดรับสมัคร (closed)**
   (`set_tournament_status`)
3. **ส่งออกรายชื่อให้ MacMahon** — `/admin/registrations` → การ์ดส่งออกด้านบน
   (`components/admin/ParticipantsExport.tsx`):
   - **CSV** ทั้งงาน (เก็บไว้เป็นหลักฐาน/ทำป้ายชื่อ)
   - **`.txt` ต่อรุ่น (zip)** สำหรับ MacMahon
   - ติ๊ก **"รวมรายที่รอตรวจสอบ"** เฉพาะเมื่อยอมรับคนที่ยังไม่ยืนยัน (ค่าเริ่มต้น = ยืนยันแล้วเท่านั้น)
   - ติ๊ก **"ใส่ระดับฝีมือจริงในไฟล์ TXT"** ได้ ถ้าไม่อยากคีย์ระดับใหม่ในโปรแกรม —
     **แต่ต้องไปตรวจในโปรแกรม MacMahon ว่าระดับเข้าครบก่อนจับคู่** ค่าปกติของไฟล์นี้คือใส่
     `35K` ให้ทุกคนแล้วคีย์ระดับในโปรแกรมเอง
4. **สำรองข้อมูล** — free plan **ไม่มี point-in-time recovery** ก่อนวันงาน (และก่อน apply
   migration ทุกครั้ง) ให้รัน export ตาม [BACKUP-RESTORE.md](./BACKUP-RESTORE.md)
   · โฟลเดอร์ `backups/` มีข้อมูลส่วนบุคคลจริง **เข้ารหัสไว้ และลบเมื่อเสร็จงาน**
5. **ตรวจว่าระบบพร้อม** — `curl https://<domain>/api/health` ต้องได้ **200 กับ `"ok": true`**
   (คำตอบถูก cache 1 นาทีต่อ lambda) · **อย่า** ใช้ `/live/snapshot` เป็นตัววัด: มันตอบ 200
   พร้อมกระดานว่างแม้ query จะพัง
6. **ตรวจ "ความพร้อมก่อนเริ่มแข่ง"** — `/admin/live` มีเช็กลิสต์ 4 ข้อให้แล้ว: token ของรายการ,
   รุ่นแข่งบนกระดาน, กรรมการของรายการนี้, และกรรมการมีชื่อในโปรไฟล์ · ข้อไหนเป็นสีแดง
   = กรรมการยังบันทึกผลไม่ได้

## 4) เช้าวันแข่ง

1. **ตั้งค่าโปรแกรม MacMahon** — `/admin/live` → หัวข้อ **"ตั้งค่าโปรแกรม MacMahon
   (launcher.properties)"** คัดลอกสองบรรทัดลงไฟล์ `launcher.properties` **ของเครื่องที่รัน
   รายการนี้**:

   ```
   tesuji.url=https://<domain>
   tesuji.token=<token ของงานนี้>
   ```

   **token แยกต่องาน** — token ของงานหนึ่งเขียนรุ่นของงานอื่นไม่ได้เลย (`_can_write_division`)
   ถ้าช่องค่าขึ้น `…` หรือ "อ่านไม่สำเร็จ" **ห้ามคัดลอก** — ต้องแก้ให้อ่านค่าได้จริงก่อน
   (เคยมีเคสคัดลอกจุดสามจุดไปใส่ไฟล์ตอนเช้าวันแข่ง)
2. **อัปโหลดคู่จับรอบแรกจาก MacMahon** ("Export Pairings") — นี่คือสิ่งที่ทำให้ **รุ่น**
   ไปปรากฏบนกระดาน (`POST /api/divisions` สร้างรุ่นใต้งานของ token เสมอ; `live_upsert_division`
   หางานจาก token) ก่อนขั้นนี้กระดานจะไม่มีอะไรเลย ซึ่งเป็นเรื่องปกติ ไม่ใช่ระบบเสีย
3. **เปิดกระดานผลสด** — `/live/<tid>` (เข้าจากฮับ `/results` ได้ ไม่ต้องล็อกอิน) ดูว่ารุ่นและ
   คู่จับขึ้นครบ
4. **แจกลิงก์กรรมการ** และให้ทุกคนเปิด + ล็อกอินให้เรียบร้อย **ก่อน** เริ่มแข่ง
5. **ส่งประกาศขึ้นหน้างาน** (ถ้าต้องการ) — `/admin/live` → 📢 ประกาศถึงหน้างาน
   (`live_set_config`) ขึ้นทั้งกระดานผลและคอนโซลกรรมการภายในราว 3 วินาที · **งานหนึ่งมี
   ประกาศได้ครั้งละหนึ่งอัน** ส่งใหม่ = แทนที่อันเดิม, ล้างข้อความ = เอาแบนเนอร์ออก

## 5) ระหว่างแข่ง

- **ติดตามความคืบหน้า** — `/admin/live` → **"สถานะรอบปัจจุบัน"** บอกรอบล่าสุดของแต่ละรุ่น
  และจำนวนโต๊ะที่มีผลแล้ว (`3/8 โต๊ะ`) พร้อม toast เมื่อรอบใดผลครบ · "ครบ" หมายถึง
  **รอบปัจจุบัน** เท่านั้น ระบบไม่รู้ว่ารุ่นหนึ่งมีทั้งหมดกี่รอบ (MacMahon อัปโหลดทีละรอบ)
- **ตารางคะแนน (Wall List)** — อัปโหลดจาก MacMahon ("Export Wall List") แล้วดูได้ในหน้าเดียวกัน
- **คนไม่มา** — กรรมการกดเช็คอิน/ไม่มาในคอนโซล ชื่อที่ถูกมาร์คจะขึ้นชิป "ไม่มา" ทั้งใน
  กระดานและหน้าแอดมิน

### อัปโหลดรอบซ้ำ (re-export pairings)

MacMahon เรียก `live_replace_round` **ทุกครั้ง** ที่กด "Export Pairings" ไม่ว่าจะเพื่อแก้คู่
เดียว เพิ่มคนมาสาย หรือกดเพราะความเคยชิน

- **หลัง `20260915_0005` ถูก apply:** ปลอดภัย โต๊ะที่ผู้เล่นสองคนเดิม **เก็บผล/หมายเหตุ/
  เช็คอิน/ไม่มา/force ไว้ทั้งหมด**; โต๊ะที่เปลี่ยนคู่ถือเป็นแมตช์ใหม่จึงล้างค่าที่กรรมการกรอก
  (ผลของ A-vs-B ต้องไม่ค้างอยู่บน C-vs-D); โต๊ะที่หายไปจาก payload ถูกลบเหมือนเดิม
- **ก่อนถูก apply (สถานะวันนี้):** การอัปโหลดซ้ำ **ล้างผลและการเช็คอินของรอบนั้นทั้งรุ่น**
  ทันทีทั้งบนกระดานสาธารณะและในทุกคอนโซล **ไม่มี backup ของ `live_match` และไม่มี
  audit trail** — การกู้คือคีย์ผลทั้งรอบใหม่จากความจำ ดังนั้นระหว่างนี้:
  **อัปโหลดรอบที่กำลังแข่งซ้ำได้เฉพาะเมื่อยอมกรอกผลรอบนั้นใหม่ทั้งหมด**
- **ตั้งใจล้างรอบจริง ๆ** — `/admin/live` → ปุ่ม 🗑 **"ลบผลจับคู่รอบนี้"** (`live_delete_round`)
  มีขั้นยืนยันก่อน แล้วอัปโหลดใหม่จาก MacMahon

### ให้คนหน้างานเข้าดูกระดานบน wifi ของสถานที่

- กระดานเป็น **URL สาธารณะ ไม่ต้องล็อกอิน**: `https://<domain>/live/<tid>` · `tid` เป็น UUID
  พิมพ์ตามไม่ได้ ให้แจกผ่าน **ฮับ `/results`** (งานที่แข่งวันนี้ขึ้นก่อน) หรือทำ QR ของลิงก์
  เต็มไปติดหน้างาน
- **เน็ตช้าไม่เป็นปัญหาเท่าที่กลัว** — เบราว์เซอร์ poll `/live/snapshot?t=<tid>` ทุก 3 วินาที
  และคำตอบถูกแชร์แคชที่ CDN (`s-maxage=3`) ดังนั้นคนดู 10 คนหรือ 300 คนก็กิน origin
  ประมาณ **1 ครั้งต่อ 3 วินาที** เท่ากัน; แท็บที่ถูกซ่อนหยุด poll เอง
- payload ของกระดานเป็น **ชื่อผู้เล่น** จึงตั้ง `noindex` ไว้ — เป็นข้อมูลสาธารณะ แต่ไม่ควร
  ไปโผล่ในผลค้นหา

### กระดานว่าง หรือขึ้น "ข้อมูลค้าง" — ไล่ตามนี้

1. **มีป้าย "ข้อมูลค้าง / STALE" ไหม** ป้ายนี้ขึ้นเมื่อ poll ไม่สำเร็จราว 15 วินาที (≈5 ครั้ง)
   = **ปัญหาเน็ตของเครื่องที่เปิดดู** ไม่ใช่ข้อมูลหาย → ลองเน็ตอื่น/รีเฟรช
2. **ไม่มีป้าย แต่กระดานว่าง** = poll สำเร็จแต่ข้อมูลว่างจริง ไล่ตามลำดับ:
   - **ยังไม่ได้อัปโหลดคู่จับจาก MacMahon** (สาเหตุที่พบบ่อยที่สุด) — ดูข้อ 4.2
   - **`tid` ผิดงาน** — view-source ดู `window.__LIVE_TID` เทียบกับงานที่เลือกใน `/admin/live`
   - **build ชี้ผิดโปรเจกต์** — view-source ดู `window.__SUPABASE_URL` ว่าเป็น ref ของ production
   - **schema ไม่ตรงกับโค้ดที่ deploy** — `curl /api/health` ถ้าได้ 503 คือข้อนี้
     (`/live/snapshot` จะตอบ 200 พร้อมกระดานว่าง เพราะ `buildFullUpdate` แปลง query
     ที่ error เป็น `[]`) · ใน log ของเซิร์ฟเวอร์จะมีบรรทัด `[live] … query failed`
   - **สคริปต์ boot ของหน้าพัง** — เปิด console ของเบราว์เซอร์: ถ้าเจอ
     `Unexpected identifier 'window'` คือกับดักเก่าที่ minifier กลืนเซมิโคลอนระหว่าง
     template literal ที่ต่อกัน แล้ว `window.__LIVE_TID` ไม่ถูกตั้ง (แก้แล้วใน `a130561`
     ด้วยการ emit **คำสั่งเดียว** — ถ้าจะแก้ `lib/live/shell.ts` ต้องคงรูปนี้ไว้ และ diff
     ต้นฉบับกับไฟล์ใน `.next/server/**` ก่อนเชื่อ)
3. **กรรมการบันทึกผลไม่ได้** — เกือบทุกครั้งคือ 2 เงื่อนไขในข้อ 2: ไม่ได้ล็อกอินใน
   เบราว์เซอร์เดียวกับลิงก์ หรือโปรไฟล์ไม่มีชื่อภาษาไทย · ถ้าคอนโซลว่างทั้งหน้า
   ให้ตรวจว่า token ในลิงก์เป็นของงานนี้ (`live_token_tournament`)

## 6) หลังงาน

1. **บันทึกรางวัล** — `/admin/awards`: อัปโหลดไฟล์ `.xml` ที่เซฟจาก MacMahon (ไฟล์ละรุ่น)
   ระบบจัดอันดับให้ (**แต้ม → SOS → SOSOS** ตามเกณฑ์ในไฟล์) → เลือกจำนวนอันดับที่ให้รางวัล
   (สูงสุด 10) → **ตรวจ/แก้ได้ทุกช่องก่อนบันทึก** (เตือนเมื่อคะแนนเสมอกันพอดีตรงเส้นรางวัล,
   ตัดผู้เล่นตัวแทนบายทิ้ง) → เขียนเข้าฐาน AWARD ผ่าน `admin_append_award_rows`
   แบบ **ต่อท้าย + idempotent** (นำเข้ารุ่นเดิมของงานเดิมซ้ำ = แทนที่ของเก่า)
   แล้วซิงก์ระดับฝีมือของผู้ที่ลิงก์ไว้ต่อทันที
2. ⚠️ **master sheet ยังเป็นแหล่งข้อมูลหลัก** — ดาวน์โหลด `.xlsx` จากหน้านั้น
   (โครงคอลัมน์ตรงกับ master sheet) ไปวางต่อในชีตกลาง **ให้เสร็จ** เพราะการ Sync ฐาน AWARD
   ทั้งชุดครั้งถัดไปเป็นแบบแทนที่ทั้งหมด แถวที่บันทึกในระบบแต่ยังไม่ได้เติมลงชีตจะหายไป
3. **ปิดสถานะงาน** — ถ้ายังไม่ได้ปิด ให้ตั้งเป็น **closed** นาฬิกาเก็บรักษาข้อมูลของ
   `purge-slips` นับจาก **วันแข่ง** และจะไม่แตะงานที่ยังไม่ `closed` เลย
4. **ลบสลิป/เลขบัญชีตามกำหนดเก็บรักษา** — เรียก edge function `purge-slips`
   **เรียกเปล่า ๆ = dry run** (รายงานว่าจะลบอะไร ไม่ลบจริง) ต้องส่ง `{"apply": true}` จึงลบ ·
   หน้าต่างเริ่มต้น 90 วันหลังวันแข่ง (ต่ำสุด 30 — ต่ำกว่านั้นคือการทำลายหลักฐานการจ่ายเงิน
   ของงานที่ยังเถียงเรื่องคืนเงินกันอยู่)
5. **สำรองข้อมูลชุดปิดงาน** ก่อนทำอะไรที่ลบข้อมูล ([BACKUP-RESTORE.md](./BACKUP-RESTORE.md))
6. **รีเซ็ต (ถ้าจะใช้ระบบต่อกับงานหน้า)** — `/admin/reset` ติ๊กเลือกกลุ่มข้อมูลที่จะลบ
   กลุ่มที่พ่วงกันถูกติ๊กให้อัตโนมัติ, ยืนยันด้วยการพิมพ์คำยืนยัน (เซิร์ฟเวอร์ตรวจซ้ำทั้ง phrase
   และ dependency) · **ลบถาวร ย้อนกลับไม่ได้** · เก็บไว้เสมอ: `app_config` และบัญชีของแอดมิน
   ที่กดเอง · ปกติงานใหม่ **ไม่ต้อง** รีเซ็ตอะไรเลย — สร้างงานใหม่แล้วคัดลอกจากงานเดิมพอ
   (หลายงานอยู่ในระบบเดียวกันได้)

## สิ่งที่ยังไม่มีในระบบ (รู้ไว้ก่อนจะไปหา)

- **ไม่มีการแจ้งเตือนทางอีเมลใด ๆ จากแอป** นอกจากอีเมลของ Supabase Auth (ยืนยันบัญชี /
  รีเซ็ตรหัสผ่าน) — และถ้ายังไม่ได้ตั้ง custom SMTP อีเมลพวกนั้นถูกจำกัดทั้งโปรเจกต์ไว้
  ระดับไม่กี่ฉบับต่อชั่วโมง ซึ่งแปลว่า "ลืมรหัสผ่าน" พร้อมกันหลายสิบคนจะเงียบไปเฉย ๆ
  ตั้งให้เสร็จก่อนวันปิดรับสมัคร ([DEV-SETUP.md § Dashboard checklist](./DEV-SETUP.md#dashboard-checklist))
- **ไม่มี audit trail ของการแก้ผลแข่งสด** — ใครแก้อะไรเมื่อไรไม่ได้ถูกบันทึกไว้นอกจากชื่อ
  คนส่งผลล่าสุด (`submitted_by`)
- **ไม่มีอุปกรณ์สำรองอัตโนมัติสำหรับกระดาน** ถ้าเน็ตของสถานที่ล่มทั้งงาน กระดานจะค้างที่
  ข้อมูลล่าสุดที่โหลดได้ (พร้อมป้าย "ข้อมูลค้าง") — แผนสำรองเป็นเรื่องนอกระบบ (พิมพ์ wall list)
